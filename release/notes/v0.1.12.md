# awx-platform-operator v0.1.12

## Operator / role / CRD changes

Gateway workloads start as their image users and satisfy the restricted Pod Security profile.

- Envoy runs as uid 101 (`envoy`). The image entrypoint only changes ownership of `/dev/stdout` when it starts as root, so that path is skipped and the container drops all capabilities.
- Jewel runs as uid 1000. Its group stays the image group so `collectstatic` can write `/opt/aap_gateway/static`.
- Managed Redis runs as uid 999. The database init Job uses the same user. The registration Job runs as uid 65534. The controller-secret Job runs as uid 1000.
- Each of those pods sets `runAsNonRoot`, `allowPrivilegeEscalation: false`, `capabilities.drop: ["ALL"]`, and `seccompProfile: RuntimeDefault`.
- The self-signed certificate init container uses the Envoy image, which already contains `openssl`.

The controller Deployment is unchanged. Its Redis sidecar still starts as root, so the namespace cannot be switched to `pod-security.kubernetes.io/enforce: restricted` yet. `task_privileged` and a hostPath projects volume are also incompatible with that profile.
