# awx-platform-operator v2026.10.29-3

Operator fixes found on a running cluster after `v2026.10.29-2`. Component image pins are unchanged.

## Operator / role / CRD changes

- **AWXPlatform reconcile failed** with `unknown playbook failure` (YAML error at line 21, column 18) since `v2026.10.29`. An indented Jinja comment in `roles/platform/templates/awx.yaml.j2` was glued onto the `image_version` line by `trim_blocks`, so the rendered child AWX was invalid YAML. CI now renders and parses the AWXPlatform child templates (`hack/ci/render-platform-templates.yml`).
- **Gateway TLS renewals broke Envoy.** cert-manager renews the self-signed gateway certificate in place every 75 days. The pod annotation meant to roll Jewel and Envoy held the Secret's name, not a hash, so neither restarted. Envoy kept the old certificate as its trust anchor, and every new connection to Jewel failed verification after Jewel next restarted. The annotation now hashes `tls.crt`, so a renewal rolls both. This rolls Jewel and Envoy once on upgrade.
- **AWXGateway CRD image defaults removed.** The schema defaulted `envoy_image_version: v1.36.6`, `redis_image_version: "7"`, `image: ghcr.io/ansible/jewel` and `image_version: latest`. The API server stores defaults in every CR, so they overrode the role defaults that releases and Dependabot update, and Envoy never left v1.36.6. The coverage check now fails on image defaults in any CRD.
- **RBAC:** the operator can delete `batch/jobs`. The gateway role removes its registration and controller-secret Jobs before re-creating them, because a Job's pod template is immutable. Those deletes were forbidden.
- **Label AWXGateway** put `name` and `namespace` outside `metadata`, so it failed on every reconcile (ignored, but noisy).

## Upgrade notes

Helm does not upgrade CRDs from `crds/` (Argo CD does). Without Argo CD, apply them first:

```bash
kubectl apply -f https://raw.githubusercontent.com/flippyboy/awx-platform-operator/v2026.10.29-3/config/crd/bases/awx.ansible.com_awxgateways.yaml
```

AWXGateway objects created by an earlier release still hold the old defaults in `spec`. Remove any of them you did not set yourself, so the role defaults apply:

```bash
kubectl -n <ns> patch awxgateway <name> --type=json -p '[
  {"op":"remove","path":"/spec/envoy_image"},
  {"op":"remove","path":"/spec/envoy_image_version"},
  {"op":"remove","path":"/spec/redis_image"},
  {"op":"remove","path":"/spec/redis_image_version"}]'
```

If Envoy logs `REST update for /v3/discovery:... failed` and its `ssl.fail_verify_error` stat climbs, restart it once: `kubectl -n <ns> rollout restart deploy/<gateway>-envoy`.
