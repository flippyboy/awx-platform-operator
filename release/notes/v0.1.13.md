# awx-platform-operator v0.1.13

## Operator / role / CRD changes

Controller and operator pods satisfy the restricted Pod Security profile.

- Web and task pods set `runAsNonRoot` and `seccompProfile: RuntimeDefault`. Every container and init container sets `allowPrivilegeEscalation: false` and `capabilities.drop: ["ALL"]`.
- AWX, rsyslog, the execution environment, and their init containers keep the image user (uid 1000, group 0).
- The controller Redis sidecar runs as uid/gid 999. The image user is root; starting as 999 skips the entrypoint's gosu step. The socket mode stays 777.
- The migration Job and the metrics-utility CronJobs use the same restricted context.
- The operator manager pod sets `seccompProfile: RuntimeDefault`.
- `AWXPlatform` no longer receives `app.kubernetes.io/managed-by: awx-operator`. Helm owns that object, so the chart label `Helm` stays. Operator-created objects, including `AWXGateway`, stay `awx-operator`.

`task_privileged`, a `development_mode` hostPath, bundled Postgres data-volume init, and Redis capabilities other than `NET_BIND_SERVICE` still cannot run in a restricted namespace. Those options stay off by default.

## Upgrade notes

Upgrade the operator chart before setting `pod-security.kubernetes.io/enforce: restricted` on the namespace. Reconcile rolls the controller web and task Deployments and the operator manager. Existing pods keep running until that rollout. A namespace label applied while `0.1.12` is still the running operator rejects the next controller or operator pod.

After this operator is running, one Helm or Argo sync of `AWXPlatform` sets `app.kubernetes.io/managed-by` back to `Helm`. Later reconciles leave that label alone.
