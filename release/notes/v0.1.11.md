# awx-platform-operator v0.1.11

## Operator / role / CRD changes

Gateway credentials are no longer copied into pod specs or ConfigMaps.

- Jewel, the database init Job, and the controller-secret Job read Postgres `username`, `password`, `host`, and `port` with `secretKeyRef`.
- `DATABASE_NAME` stays the gateway database from the CR (`database_name`, default `gateway`).
- The admin password lives in a Secret mounted as `container-startup.yml`. The registration Job reads `ADMIN_PASS` from the admin Secret.
- A Redis URL that contains credentials is stored in a Secret. `settings.py` reads `REDIS_URL` from the environment.
- Secret-bearing tasks use `no_log`.
- The trust ServiceAccount can update only `{name}-controller-service-secret`. It can no longer read every Secret in the namespace.
- Workloads that do not call the API do not mount a service-account token.
- Envoy is not forced to uid 0, drops all capabilities, and no longer publishes admin port 19000 on its Service. The readiness probe still uses the container port.
- When the operator issues the TLS certificate, Envoy and the registration Job verify it. User-supplied certificates stay unverified so custom SANs keep working.

## Upgrade notes

Reconcile rolls Jewel and Envoy. The application still receives `DATABASE_PASSWORD` and the startup file at the same path. Anything that called the Envoy admin API on Service port 19000 needs another path; that port is no longer part of the Service.

Managed Redis is still unauthenticated.
