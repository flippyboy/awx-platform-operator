# awx-platform-operator v0.1.9

## Fix: AWXGateway boolean fields sent as strings (API 422)

v0.1.8 quoted Jinja in the AWXPlatform playbook so Ansible could parse
`default(true)`. The API then rejected the child CR:

```text
spec.create_certificate in body must be of type boolean: "string"
spec.create_tls_issuer in body must be of type boolean: "string"
```

Child `AWXGateway` / `AWX` manifests are now Jinja templates applied with
`lookup('template') | from_yaml`, so booleans and lists are native types.

Also fixed (was ignored): Label AWXPlatform must set `metadata.namespace`
(top-level `namespace` is not valid for that GVK).

## Guardrails (same class of bug)

- Typed `controller_service_https` (boolean) and `controller_service_port` (string)
  on AWXGateway / AWXPlatform so a stringified bool 422s at apply time.
- `hack/scripts/check-cr-types.py` renders the templates (including
  stringified `"true"`/`"false"` like ansible-operator) and checks Helm
  output against CRD types. Wired into CI.
